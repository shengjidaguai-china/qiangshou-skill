# 事实与策略

## 1. 素材读取顺序

先读第一方材料，再用外部来源补充：

1. 用户亲述、访谈与语音转写
2. README、许可证、架构和产品文档
3. 关键代码、测试、日志、提交与时间线
4. 原始评论、issue 和反馈截图
5. 官方文档、原始研究和权威数据
6. 二手报道与第三方分析

不要因仓库完整而忽略作者真实动机，也不要因故事好听而跳过项目证据。

## 2. 事实表

写作前记录计划进入正文的关键说法：

| 编号 | 候选说法 | 类型 | 来源或位置 | 时间 | 可验证程度 | 发布口径与风险 |
| --- | --- | --- | --- | --- | --- | --- |
| F01 |  | 仓库可验证 | 文件、行或提交 |  | 高/中/低 |  |
| F02 |  | 用户亲述 | 当前对话或访谈 |  | 高/中/低 |  |
| F03 |  | 第三方反馈 | 评论或截图 |  | 高/中/低 |  |
| F04 |  | 推断 | 推理依据 |  | 高/中/低 |  |
| F05 |  | 时效数据 | 页面与查询日期 |  | 高/中/低 |  |

- **仓库可验证**：可以直接陈述，但确认本地与线上版本是否一致。
- **用户亲述**：按第一人称经历写；必要时用“按我的记录”或“大约”，不能伪装成仓库证据。
- **第三方反馈**：明确写“有用户反馈”或“对方告诉我”；单个反馈不是实验结论。
- **推断**：使用“我判断”“可能”“从这些现象看”；证据不足时降级或移出正文。
- **时效数据**：写明“截至 YYYY-MM-DD”，发布前按需要重新核验。

## 3. 必须守住的口径

### 数字与效果

- 区分精确统计、估算、约数和营销口径。
- 说明分母、范围、基线、测量方法与日期；百分比要回答“什么相对什么变化”。
- 不把文件、阶段、常驻上下文或单次实验的变化外推成所有场景总效果。
- 字符、字节、Token、行数、平均数和中位数不能互换。
- 没有遥测或对照实验时，不写“证明有效”“成功率”；用户反馈必须归因。

### 引语与用户原话

- 只有可见原文或用户明确确认的原话才能加引号；记忆中的大意使用转述。
- 保留用户明确选择的措辞，不为标准化、连贯或高级感改写。
- 截图公开前匿名化头像、昵称、联系方式和私人信息。

### 高风险与许可证

- 医疗、法律、心理和关系内容避免诊断、保证或替代专业服务的暗示。
- 读取许可证全文和仓库声明，区分“开源”“源码公开”“非商业免费”和“商业授权”。
- GitHub 界面未识别许可证不代表没有许可证，以仓库实际文件为准。

## 4. 策略卡

写标题前确定：

| 维度 | 决定 |
| --- | --- |
| 目标读者 | 身份、经验与当前困惑 |
| 传播承诺 | 读完能理解、学会或重新判断什么 |
| 主问题 | 主角想要什么，或作者质疑什么 |
| 阻力/矛盾 | 哪两个目标不能轻易同时满足 |
| 技术/证据主线 | 真正改变结果的 1–2 个选择或证据链 |
| 变化曲线 | 人物、项目或认知怎样变化 |
| 结尾回扣 | 回到哪个事件、问题或动机 |
| 自然行动 | 试用、安装、讨论、贡献或验证 |

传播承诺必须具体且能兑现，避免“感受技术改变世界”式空话。

## 5. 标题筛选

标题可以直接提问，也可组合数字、投入、结果、反差或身份。只选正文能兑现的元素，并检查：

1. 最强说法是否有来源、范围和日期？
2. 是否同时说明发生了什么或为什么值得读？
3. 是否把单个反馈、局部数字或身份包装成普遍效果？
4. 是否依赖夸张词而不是信息差？

优先选择事实可靠、问题清楚、与目标读者相关的版本，不以“更炸”作为唯一标准。
