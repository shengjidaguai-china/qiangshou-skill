# 轻量自进化

仅在终稿触发后读取。目标是学习可跨文章复用的偏好，不复刻某篇文章。

## 1. 触发与样本

满足任一条件即触发：用户明确确认终稿；或本次写作已经同时交付配图和公众号可复制 HTML。触发表示“可以检查学习”，不表示一定新增规则。

交付组合需要确定性确认时运行 `python3 scripts/self_evolution.py trigger --deliverable visuals --deliverable wechat_copyable_html`；返回 `final: true` 后进入终稿保护并继续本流程。

优先使用本轮模型前稿与用户手改终稿。找不到可靠前稿、无法确认修改者，或只有模型自己生成的成稿时，不推断偏好；只记录用户在对话中明确说过的规则。用户说“这次不要学习”时完全跳过。

## 2. 差异与归因

按真实前后稿区分四类：

| 类型 | 归因 | 能否作为偏好证据 |
| --- | --- | --- |
| 删除 | 用户删除了模型文字 | 可以，归纳删减方向 |
| 改写 | 用户把模型文字改成另一种表达 | 可以，对照前后归纳 |
| 新增 | 用户加入前稿没有的文字或视觉处理 | 可以，但单篇不晋升 |
| 原样保留 | 助手原文被保留 | 不可以，禁止称为用户写作 |

运行确定性差异清单。脚本会忽略标题、独立图片和 Markdown 排版，并把混合替换块拆成删除、改写与新增：

```bash
python3 scripts/self_evolution.py diff <模型前稿.md> <用户终稿.md> --domain text
```

脚本只向标准输出返回临时 JSON，不写差异报告。不要把输出复制进长期记忆。

## 3. 晋升规则

- 用户明确指令立即成为有效规则；同类冲突时，最新明确指令覆盖旧规则和旧终稿信号。
- 推断偏好先进入对应记忆的“待观察”，只保存抽象方向与匿名样本计数，不保存原句。至少两个不同的用户确认终稿重复出现同一方向后才晋升。
- 同一终稿重复分析只算一次。单篇章节结构、推进线、局部写法、一次标题选择、项目事实和临时排版都属于临时策略，不能进入文字或视觉记忆，也不能晋升为固定引擎。
- 每次跨两套记忆合计最多新增或修正 2 条；每套最多 15 条有效规则。合并同义项，删除被新明确指令覆盖的旧项。

先生成不含路径和正文的稳定匿名样本 ID：

```bash
python3 scripts/self_evolution.py source-id <用户终稿.md> --domain text
```

ID 基于去除排版后的内容生成，同一终稿增加标题、粗体或图片后不会重复计数。视觉信号改用 `--domain visual`。只把归纳后的抽象规则写入台账；文字和视觉分别记录。第一篇进入待观察，第二个不同终稿的同 key 信号自动晋升；明确指令加 `--explicit` 立即生效，冲突旧 key 用 `--supersedes`：

```bash
python3 scripts/self_evolution.py record --domain text \
  --key concise-real-lists --rule "列表只用于真实步骤和判断标准" \
  --source-id final-text-0123456789abcdef
```

脚本原子更新对应的 `*-signals.json` 台账和 Markdown 记忆。同一终稿 ID 对同一 key 只计一次；已有明确规则不会被之后的推断覆盖。key、source ID 与规则不得包含项目名、人物、事实或私人内容。

## 4. 两套记忆

- `author-voice.md`：文案、句长、口语、删减、列表和 AI 味。
- `visual-preferences.md`：配图类型、裁剪、拼图、封面构图和排版偏好。

对应的 `author-voice-signals.json` 与 `visual-preference-signals.json` 只保存抽象规则、匿名来源 ID、状态和顺序，是确定性晋升依据；不要直接手改 Markdown 记忆而跳过台账。

视觉没有可靠前后对照时同样只记录明确指令。模型自己选择的图片、裁剪或版式不能因为完成交付就变成用户偏好。

长期记忆不得保存终稿全文或片段、事实、数字、观点、结论、人名、项目名、奖项、私人内容、文件路径或临时差异报告。历史基线包含多篇已确认手改终稿；新增单篇不得覆盖既有跨稿规则。
