## 1. 共通推进原则

让每一节至少发生一种变化：

- 作者或读者知道了新事实
- 项目状态或实验判断发生变化
- 一个选择产生代价
- 解决方案暴露新问题
- 反馈改变方向
- 数字推翻原先预期

用“所以 / 但是”检验相邻段落。只能用“然后”连接时，多半是流水账；只能用“此外”连接时，多半是功能介绍。

章节内部可使用这条因果链，但不要把它写成固定小标题：

`进入问题 → 场景或证据 → 为什么难 → 作者判断 → 行动或取舍 → 结果 → 新问题`

每章从上一章的真实后果进入，离开时改变人物、项目或判断。连续两节只在解释“它能做什么”时，把功能放回触发它的事件、反馈、失败或取舍。

## 2. 项目故事

### 五幕：素材丰富的项目复盘

1. **起因与阻力**：交代人物动机、目标和最初失落。
2. **意外上线或被迫行动**：让外部世界打乱计划。
3. **反馈与冲突**：评论、用户或失败同时带来鼓励与压力。
4. **技术取舍与反转**：展示最难的选择、代价和工程结果。
5. **结果、边界与邀请**：回扣初心，说明现在能做什么、不能做什么以及如何参与。

素材集中时用四幕：

1. 目标与错误预期
2. 失败扩大、代价显现
3. 找到根因并做出取舍
4. 结果、边界与可复用经验

不要为了对称给每一幕相同字数或小标题数量。故事的核心不是功能多少，而是人物面对限制时怎样判断、选择和改变。

### 功能回到事件

不要单独铺长功能清单。写清功能为什么出现：

- 用户拿不到可发送的话术，因此先改第一屏。
- 截图与转述被混为事实，因此增加证据边界。
- 系统过度推进，因此增加停止条件。
- 资料持续膨胀，因此改为内核加按需加载。

只有读者需要快速判断是否适用时，才在结尾附近给短功能地图。

## 3. 观点实证长文

适用于作者质疑一种流行认知，并有个人经历、实验、数据或权威材料可以验证。推荐推进：

`大众认知 → 作者为什么怀疑 → 公平对比 → 意外发现 → 实验验证 → 可执行方法 → 价值收束`

### 写作要求

- 标题可以直接提问，不强行堆数字、奖项、身份或反差。
- 先把对方观点写到其支持者也会认可，再提出质疑；不要为了反驳制造稻草人。
- 比较实验要说明共同条件、变量、样本、验收标准和后出现的信息。
- 允许结果与作者最初预期不同。诚实改判比硬凑立场更可信。
- 分开写实验观察、第三方研究与作者判断，避免把相关性写成因果。
- 核心观点可以鲜明，但在数字、研究和外部证据处补必要边界；正文继续说人话，不写成论文。
- 方法尽量压缩成普通读者能记住的约三步。只有确有必要时才增加并列步骤。
- 结尾从技术结论回到普通人的机会、判断与行动，不做空泛升华。

实验结果不能单独替代论证。解释为什么出现这个结果、它在哪些条件下成立，以及什么新证据会让作者改变判断。

## 4. 开场与章末

### 前三屏

前三屏完成四件事：

1. 第一行让事情、冲突或问题发生。
2. 三句内出现真实数字、反差或明确疑问。
3. 尽快说清项目或议题是什么。
4. 留下正文会回答的问题。

可以从结果、日志、评论、两个数字的反差或一次失败动作进入。不要从“近年来”“随着 AI 发展”“在数字化浪潮下”、市场规模或完整功能开始。

### 章末钩子

钩子必须来自下一章真实存在的未解问题、反差、后果、选择或人物动作。下一章应成为必要答案。

禁止使用“更精彩的还在后面”“真正的挑战才刚刚开始”“事情远没有那么简单”等空悬念。删掉钩子而下一章毫无损失时，钩子只是装饰。

## 5. 技术段落

重要技术选择尽量写清六件事：

1. **问题**：具体失败现象是什么？
2. **为什么难**：限制、冲突和错误直觉是什么？
3. **尝试与取舍**：试过什么、放弃什么、为什么？
4. **具体实现**：文件、模块、路由、测试或关键机制。
5. **量化结果**：基线、范围、测量方法与结果。
6. **适用边界**：在哪些场景不成立，还有哪些变量未验证。

术语第一次出现时，用一句功能性人话解释，随后立即回到项目事实。不要连续堆比喻，也不要粘贴大段代码冒充深度。

数字要守住口径：区分单次与多次测量、平均数与中位数、局部与整体、字符与 Token、实验结果与用户反馈。无法量化时，直接写目前能观察到什么。

技术深度来自真实问题、限制、失败、实现与边界，不来自术语密度。

## 6. 作者声音与去 AI 味

声音来自经历与判断，不来自身份标签。

- 保留作者为什么做、何时高兴或不服、如何判断意见、哪里没有验证、为何改变主意。
- 允许自然口语、自嘲、吐槽和反击；不要为了高级感替换作者已经选择的词。
- 不自动添加“姐妹们”“宝子们”“绝绝子”等刻板话术。
- 不把女性身份写成天生感性、不懂技术或更会表达。
- 不为了强硬持续攻击，也不为了谦逊抹掉技术判断。

第一人称只在“我做了、判断了、感到或改变主意”有信息时出现，不按频率硬塞。

### 去 AI 味

优先删除掩盖真实因果的模板表达，如“随着……发展”“值得一提的是”“综上所述”“赋能”“闭环”“底层逻辑”。不要见词就删，先判断它是否准确。

避免生成式指纹：

- 每节使用相同长度标题或相同起承转合
- 每段都是“观点 + 三项排比 + 金句”
- 连续使用“不是……而是……”
- 反转和金句过密
- 为显得真人而编口头禅、小失误或情绪

用证据替换形容词：“爆火”给范围与日期，“巨大工程”给材料量或时长，“效果好”说明谁观察到什么和没有验证什么。

金句应是正文新判断的自然压缩，不按篇幅配额制造。幽默用于展现人物或释放压力，不能篡改事实、羞辱弱者或抢走主线。

## 7. 移动端节奏

- 多数段落保持 1–3 句；复杂技术解释可以略长。
- 一个段落只承担一个主要动作或判断。
- 关键转折、代价和结论可以独立成段。
- 长句铺信息，短句做停顿；不要把每句都切成口号。
- 连续三段长度或句式相同时，主动打破节奏。
- 小标题只在叙事任务变化时出现，不按字数机械添加。

表格适合版本对比、时间线、技术映射和方案取舍；列表适合步骤、条件和快速扫读。情绪高潮与人物冲突优先写成场景和因果。

## 8. 配图与参考文章

先完整读取参考文章，再提取叙事、文案、版式和视觉规律。只学习可迁移结构，不复制独特标题、连续句子、口头禅、私人经历、品牌色或图形资产。

配图只承担三种核心作用：

1. **证据**：评论、日志、提交、反馈、数据或结果。
2. **解释**：流程、架构、时间线或概念关系。
3. **转折**：前后对比、失败与结果、投入与产出的变化。

优先真实截图和第一方数据；示意图不能伪装成产品截图或统计。每张图只表达一个重点，正文与图片接力，不逐字重复。默认输出独立配图蓝图；不要把图片锚点和编辑备注混入干净正文。

## 9. 自检

- 开场是否立即出现真实事件、问题、数字或反差？
- 每章是否改变事实、项目、人物或判断？
- 上一章结果是否推出下一章问题？
- 项目故事是否写出人物选择，观点文章是否公平呈现对方？
- 技术段落是否包含实现、结果和边界？
- 数字、研究、反馈和作者判断是否分清？
- 是否保留作者自然口语，又没有表演真人感？
- 是否存在功能目录、空钩子、模板排比或重复信息？
- 配图是否只用于证据、解释或转折？
- 用户原话、终稿与已删除内容是否得到保护？
